| Basic properties of languages | **Regular languages**:<br>- If $L$ is finite, $L$ is regular (because we can enumerate strings).<br>- If $L$ is regular, $L$ can be expressed by a DFA/NFA (Thompson's theorem).<br>- If $A, B$ are regular, then $A \cup B$ is regular because we can connect in parallel the two DFAs for $A$ and $B$. <br>- If $A,B$ are regular, $A \cap B$ is hard to tell, since there is no intuitive way to express it. It could be non-regular. <br>- If $A, B$ are regular, then $A+B$ defined by concatenating a string in $A$ and a string in $B$ is regular, because we can connect the two DFAs in series, so that all accepting states in one DFA lead to to the starting state of another DFA. <br><br>**Kleen Star**<br>- The kleen star over an alphabet $\Sigma^*$  contains all possible combinations of letters in the alphabet (without strings of infinite length).<br>- The kleen star over a language $L^*$ is similar.<br>- If $L$ is regular, then $\bar{L} = \Sigma^* - L$ is regular because we can swap the accepting and rejecting states for the language $L$.<br>- If $L$ is regular, then $L^*$ is regular because we can apply the kleen star to the regular expression.<br><br>**CFGs**<br>- If $L$ is regular, $L$ is a CFG. <br>- not all CFGs can be expressed using a DFA/NFA, but all can be encoded into a turing machine. <br>- If $L$ is a CFG, is $\bar{L}$ a CFG?<br>- If $A, B$ are CFGs, then $A \cup B$ is regular because we can take the start literal for the new language to be either $A$ or $B$. <br>- If $A,B$ are CFGs, $A \cap B$ is hard to tell, since there is no intuitive way to express it.<br>- If $A, B$ are CFGs, then $A+B$ defined by concatenating a string in $A$ and a string in $B$ is a CFG because we can connect the starting literals in the expression for the new language. <br>- If $L$ is a CFG, then $L^*$ is a CFG because we can apply the kleen star for $L^*$ by appending the literal for $L$ to the start of the literal for $L^*$. |           |         |
| DFA/NFAs                      | DFA: deterministic finite automata, is a directed graph consisting of accepting states and transitions (edges) with characters from an alphabet. Explicitly, it is a five tuple $(Q,S,\Sigma, \delta, A)$, representing all states, starting states, the alphabet, the transition rules, and the accepting state, respectively. For DFAs specifically, there must be a unique starting state. The logic is like "I can always figure out what state to accept". <br><br>We can connect DFAs in series, parallel, and even take products like cartesian products. Under a product construction, all states are pairs of states. The start states are the product of two start states, and the transitions apply separately to each element. We can modify the accepting states to accept if accepts both $A$ and $B$, or accept if accepts $A$ and rejects $B$, or accept if rejecting both $A$ and $B$. For a product of $n$ DFAs, there are $2^n$ choices. <br><br>NFA: nondeterministic FA is a modification from a DFA. The main difference is that NFAs can have multiple start states and multiple transitions from one state to other states using the same literal. There can also be $\epsilon$ transitions (magic jumps). Acceptance under an NFA is like "there's some chance I will accept some state".<br><br>Thompson showed that DFAs are equivalent to NFAs and can all express regular languages.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |           |         |

| NP hardness                   | To show that problem A is NP hard, we can reduce from an existing NP hard problem B, to show that if there is a black box that solves A, it can use the solution to solve $B$ in polynomial time.<br><br>Given problem $B$ with input $x$, we can transform $x$ into a new input $x'$ in polynomial time, and then run $x'$ on $A$ so that $A$ solves $x'$ in some way, and use that information on $B$. <br><br>Generally, we need to show that  $A$ solves $x'$ if and only if $B$ solves $x$. With the two directions being if $A$ solves $x'$ and if $A$ doesn't solve $x'$ (due to the contrapositive).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |           |         |

Since all NP hard problems reduce from one another, showing that one problem reduces to another NP hard problem is sufficient to show that it is NP hard. <br>NP-complete: Problems that are NP hard and NP are NP complete.<br>                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |           |         |

| Decidability definitions      | A turing machine takes strings as input. Given some string $s$, a turing machine $MIT$ could either<br>1. accept $s$ into $MIT$ as a busy beaver<br>2. reject $s$ <br>3. put $s$ on a waitlist to never be resolved (diverges)<br><br>For a language $L$ and a turing machine $MIT$, if for all strings $s \in L$, $s$ is either accepted by $MIT$ or rejected by $MIT$, then $MIT$ decides $L$. If $L$ is an elite school and all $s \in L$ are accepted by $MIT$, then $MIT$ accepts $L$; there is also the case where $MIT$ rejects $L$, but that is quite sad. If there is some $s$ that $MIT$ diverges on, then $L$ is not decided by $MIT$. <br><br>We call a language $L$ to be undecidable if there are no turing machines $M$ that decide $L$.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |           |         |
